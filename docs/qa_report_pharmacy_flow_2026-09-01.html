5. Doctor Self-Service Registration (added 2026-09-04)
Backend branch feature/doctor-self-service-registration (clinic-reservations) + frontend branch feature/doctor-self-service-registration (med-super), tested live against a running local backend + real Postgres.
Doctor self-registration (full form + photo + working hours + submit)
Fields sentFull name, specialty, degree, email, phone, experience years, bio, license number, real profile photo, clinic name/address/city/region, consultation fee, working days (enabled days with From/To times)
Current statusPersisted correctly end to end. Verified directly in the database: Doctor, User, Clinic, Address, ClinicBranch, and DoctorClinicAffiliation rows all created with the submitted values; the profile photo uploaded for real to ImageKit and its URL is stored on Doctor.photo_url; the submitted working day created a real ScheduleTemplate row tied to the new affiliation (weekday/start_time/end_time/slot_duration_minutes all correct).
  • Bug found and fixed: submitting a real (non-tiny) profile photo failed with an opaque 500 — Express's default 100kb JSON body limit rejected the base64-encoded photo before the request ever reached the backend's own validation. Fixed by raising the body-parser limit in src/main.ts to safely exceed the max encoded photo size.
  • Bug found and fixed: picking a working-hour "From" time later than "To" (or vice versa) saved silently with no warning, and only surfaced as a generic error at the very end of the multi-step form (422 INVALID_SCHEDULE_WINDOW, after clinic info, verification, and photo were already filled in). Fixed by validating the window immediately when the time is picked, with a clear inline message.
  • Bug found and fixed — real cross-account data leak: starting a registration, then exiting the app without logging out (not the same as pressing "logout"), then logging in as a different phone number, surfaced the first applicant's half-filled draft (name, email, license number, documents) on the new account. The in-progress draft is Hive-persisted and was only ever cleared by an explicit logout() call — a session that ends without one (app killed, closed, crashed) left it on disk unowned. Fixed by tagging the draft with the owner's user id and discarding it on login if it belongs to someone else.
Doctor verification-document upload (self-service)
Current statusPOST /v1/provider-verification-documents was Admin-only end to end; a doctor can now upload a document for their own record (ownership enforced server-side — a doctor cannot upload against another doctor's id or a non-doctor provider type). Wired into the registration flow: after submit returns a real doctorId, each picked document (license, national ID, specialty certificate) uploads for real, multipart, to ImageKit.
  • In this pass's test run no document was actually picked during the verification step, so the resulting doctor record has zero uploaded documents — confirmed by querying provider_verification_documents directly (empty result). The upload path itself was verified by code review and by the ownership/role-guard logic, not by an end-to-end file upload in this specific run.
